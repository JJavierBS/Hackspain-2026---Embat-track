# Phase 6 · Plan B — Frontend: Compare on showcase pairs, lead time, event marks, static fallback

> **For agentic workers:** Claude Code: use superpowers:executing-plans (or superpowers:subagent-driven-development) to run this plan task by task. Antigravity or other agents: do the checkboxes in order. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the demo story on screen. Compare opens on the showcase pair the backend picked (SPEC §10.4). The Entity page says, on the timeline and on the limit chart, **how many months earlier** the system raised its hand. Methodology stops saying "bloque 8" and shows measured anticipation and the false alarm rate per profile, plus the submission export button. And the whole app survives a dead backend through a frozen JSON snapshot (SPEC §14).

**Architecture:** Nothing changes in the stack. `src/api/types.ts` mirrors the phase 6 JSON contract. The mock generator gains lead-time, showcase-pair and event data so every screen is built before plan A's backend exists. `apiGet` gains one fallback path: on a network error or a 5xx it reads `/fallback/<key>.json`, flips a module-level flag and a banner appears. `scripts/snapshot-fallback.mjs` writes those files from a running backend.

**Tech Stack:** React 19, TypeScript 5.9, Vite 8, React Router 7, TanStack Query 5, Recharts 3, Tailwind 4, oxlint. npm. Node 24 for the snapshot script (no dependency, native `fetch`).

**Spec:** `docs/SPEC.md` §8.4, §10.4, §12.5–§12.7, §14, §15. Shared contract, decisions G1–G16 and path ownership: `docs/superpowers/plans/2026-09-19-phase6-overview.md`. **Read the overview before Task 1** — especially contract items 6 and 7.

## Global Constraints

- Edit only `frontend/**` and `scripts/snapshot-fallback.mjs`. Never edit `backend/**`, `docs/**`, `CLAUDE.md`, `docker-compose.yml`, `.gitignore`.
- UI copy in Spanish, identifiers and comments in English (CLAUDE.md conventions).
- `profile` and `month` stay in the URL (`useGlobalParams`). Compare keeps `?a=` and `?b=` so a pair is linkable.
- No weight, λ, threshold or product parameter is written in a page or component (decision E1, CLAUDE.md rule 5). Lead-time windows and thresholds come from `/api/analytics/lead-time` and `/api/methodology`. The mock generator may hold synthetic numbers: it is test data, labelled as such.
- No new npm dependency. Recharts covers every chart; reuse the look of `TrendChart` and `LimitHistoryChart`.
- Green/red only for direction, one color per band (`BANDS`). Every number has a tooltip or caption with its definition (SPEC §12.7).
- Honesty is part of the pitch (SPEC §15): every lead-time number is labelled as measured against **proxy events**, and the `OVERDUE` trigger is marked provisional (its anchors are still pending).
- Respect `prefers-reduced-motion` (the `@media` block in `src/index.css` already exists).
- Checks after every task: `npm run typecheck && npm run lint` (exit 0). `npm run build` at Tasks 6, 7 and 10.
- Commits: Conventional Commits, English, lowercase subject. Commit after each task. No AI attribution line.

### Task 7: Static fallback (SPEC §14)

**Files:**
- Modify: `frontend/src/api/client.ts`, `frontend/src/api/queries.ts`, `frontend/src/components/Layout.tsx`
- Create: `frontend/src/components/OfflineBanner.tsx`, `scripts/snapshot-fallback.mjs`

- [ ] **Step 1: The key function and the fallback read**

In `client.ts`, next to `apiGet`:
```ts
/** Contract item 7: "/portfolio?profile=BANK&month=2026-08" -> "portfolio_month_2026-08_profile_BANK". */
export function fallbackKey(path: string): string {
  const [route, query = ""] = path.split("?");
  const params = [...new URLSearchParams(query).entries()].sort(([a], [b]) => a.localeCompare(b));
  const flat = [route.replace(/^\//, ""), ...params.flat()].join("_");
  return flat.replace(/[^A-Za-z0-9_-]/g, "_");
}
```
`apiGet` keeps its current behaviour and, when `fetch` throws (network down) or the response status is
≥ 500, tries `fetch('/fallback/' + fallbackKey(path) + '.json')`. Accept it **only** when the response is
ok and its `content-type` contains `json` — nginx answers `index.html` for unknown paths (`try_files`),
so a missing snapshot would otherwise parse as HTML. On success: mark the app offline and return the
JSON. On failure: rethrow the original error. A 4xx is an answer, never a fallback.

Offline flag: a module-level `let offline = false` with `subscribe` / `getSnapshot` so a hook can read it
(`useSyncExternalStore`), exported from `client.ts` and wrapped as `useOffline()` in `queries.ts`.

- [ ] **Step 2: The banner**

`OfflineBanner` renders nothing while online. Offline: a strip at the top of `Layout`'s main area,
"Sin conexión con el servidor · datos congelados de {mes}" (the month comes from the fallback
`index.json`, fetched lazily by the banner; if it is missing, drop the month from the sentence). Static,
no animation. It must be obvious to the jury that this is a snapshot: honesty over polish (SPEC §15).

Where there is no fallback (the monitor replay, the limit simulator, any POST), the existing error state
shows — add one sentence to it: "Esta función necesita el servidor."

- [ ] **Step 3: The snapshot script**

`scripts/snapshot-fallback.mjs`, Node 24, no dependency:
```
node scripts/snapshot-fallback.mjs --api http://localhost:8080 --out frontend/public/fallback
```
It reads `/api/meta` for the last month and the profiles, then fetches and writes one file per key
(`fallbackKey` logic duplicated in the script — keep the two in sync, it is six lines):
- `/meta`, `/profiles`, `/methodology`
- per profile: `/portfolio?profile&month`, `/analytics/lead-time?profile`, `/analytics/showcase-pairs?profile&month`, `/analytics/distribution?profile&month`, `/monitor/alerts?profile&month`, `/monitor/watchlist?profile&month`
- the **showcase entities**: the ids of the first three pairs of each profile, plus the first five `examples` of each profile's lead time, deduplicated — per profile `/entities/{id}?profile&month` and `/entities/{id}/timeline?profile`.
Then `index.json` = `{ month, createdAt, keys }`. Print one line per file with its size and a total, and
exit non-zero if any fetch failed, so a bad snapshot is never committed by accident.
